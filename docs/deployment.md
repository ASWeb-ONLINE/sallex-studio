# GitHub и размещение

## Текущее состояние

[ASWeb-ONLINE/sallex-studio](https://github.com/ASWeb-ONLINE/sallex-studio) — отдельный **private**-репозиторий исходников. 15.10.2026 GitHub API отклонил включение Pages с HTTP 422: текущий тариф не поддерживает Pages для этого private-репозитория. Владелец явно выбрал: «Оставить репозиторий приватным; Pages пока не публиковать».

Публичного адреса сайта нет. Платные возможности не включались, видимость не менялась. В `.github/workflows/pages.yml` действия настройки Pages, загрузки build-артефакта и deploy запускаются только при `PAGES_ENABLED=true` и вне pull request. Эта переменная не включена. Обычные проверки разрешены и работают независимо от размещения.

## Проверки GitHub Actions

Push в main, pull request и ручной workflow_dispatch запускают:

1. Checkout исходников без сохранения токена в рабочем дереве.
2. Node из `.node-version`, pnpm 11.25.0 и установку по frozen lockfile.
3. Astro check и статическую сборку.
4. Установку Chromium на изолированном runner и 20 браузерных тестов production-сборки.
5. Измерение файлов сборки.

Официальные actions закреплены полными проверенными commit SHA, а не плавающими тегами. Для check — `contents: read`; права `pages: write` и `id-token: write` выделены только отключенному deploy job. Секреты в исходниках не нужны. Сырые screenshots/traces не загружаются в Pages; при будущей публикации передается только `dist`.

## Пути и будущая публикация

`astro.config.mjs` читает `SITE_URL` и `BASE_PATH`. Локальное значение base — `/sallex-studio/`, без фиктивного site. CI получает base из имени текущего репозитория. Когда размещение отдельно разрешено и доступно, официальный configure-pages возвращает origin для SITE_URL. Вся внутренняя адресация, шрифты, CSS, favicon, social preview и ссылка 404 используют проектный base; SPA fallback не нужен.

До нового поручения **не включать PAGES_ENABLED и не менять видимость**. При будущем разрешенном размещении:

1. Проверить доступность Pages для выбранных условий и ограничения аккаунта без включения платных услуг по умолчанию.
2. Выбрать GitHub Actions как источник Pages; затем явно включить переменную `PAGES_ENABLED=true`.
3. Запустить workflow и дождаться успешных check и deploy одного commit.
4. Открыть адрес из `steps.deployment.outputs.page_url`, не угадывать его.
5. Сверить `meta[name=build-revision]` с SHA; проверить главную, mobile, якоря, сетевые ресурсы и неизвестный маршрут/404. Только после этого считать размещение проверенным.

Preview имеет noindex/nofollow. Это просьба поисковым роботам, не контроль доступа. Переход к индексируемому коммерческому сайту и изменения контактов — отдельный осознанный этап.

## Обновление и безопасное исправление

Отредактировать файлы по карте README, выполнить `pnpm check`, `pnpm build`, `pnpm test:e2e`, оценить реальные снимки измененных экранов. Проверить `git diff`, не включать local-only, секреты и dist. Создать обычный commit и push. После push проверить [Actions](https://github.com/ASWeb-ONLINE/sallex-studio/actions) для соответствующего SHA; зеленый check сейчас не означает публикацию.

Исправление выпускается новым commit. Для отмены ошибочного изменения использовать `git revert <commit>` после проверки локального состояния, затем повторить проверки и push. Не применять force push, reset истории, замену remote или удаление чужих данных ради отката. Отмена первого коммита удаляет весь сайт, поэтому для исходной версии следует исправлять конкретные файлы новым commit.
